# Topology Keeper

## 0.29.0のエリア表示

英語UI対応として、設定画面・コマンド・メイン小窓・孤立・分析結果・部分グラフ・タグ提案・外部ファイル操作・取り込み復旧・整理時の確認と通知を日英辞書へ移行しました。Obsidianの表示言語が日本語なら日本語、それ以外は英語を使用します。言語変更後はプラグインを再読み込みしてください。画像読み込みなどの内部例外・開発ログには日本語が残る場合があります。英語UIとモーダルの表示は利用者確認済みですが、全画面・画面幅の網羅的な確認は未完了です。

「孤立」はVault全体の通常ノートを対象にします。ほかの通常ノートとの直接リンク（入出力）も共通タグでの接続もないものを要確認として数えます。「タグのみで接続」は別表示です。設定の「孤立チェック対象外のフォルダ」に `未分類` などVault内の相対パスを指定すると、配下のサブフォルダも要確認の件数から外し、「孤立チェック対象外」に表示します。空欄なら許容フォルダは指定しません。ノートの移動・削除は行いません。従来のメタノート等の整理は孤立ウィンドウ内の「管理データの整理」に折り畳んで残しています。

タグの付与先がほかのタグや直接リンクでもまとまっているかを自動評価します。候補タグ自身は根拠に含めず、広く使われる他タグの寄与も抑えます。根拠が十分でまとまりが弱いタグは、領域分割への影響を弱めますが、タグや横断関係は除外しません。材料不足のタグは重みを維持します。結合領域の展開先で評価理由を確認できます。これは構造に基づく暫定的な推定で、「日記」「話題」などの意味を断定するものではありません。

タグを通らない直接リンクで十分なまとまりが複数確認できる場合は、その分割を優先します。共通タグは領域間の接続として保持するため、タグ一つだけで既存のまとまりが大きく統合されることを抑えます。直接リンクの根拠が不足する場合には従来の重み付き分割を用います。

部分グラフウィンドウは、タイトルバーで移動した位置と右下で変更したサイズを保存し、再表示・プラグイン再読み込み後に復元します。画面からはみ出す場合は表示範囲内へ補正します。

分析結果の各領域（平面・非平面・ホットスポット・ホットスポット外の未判定）を展開すると、その内部の「素領域」と、共通タグによる「結合領域」を確認できます。素領域は親の範囲内で直接リンクによってつながるノート群で、二ノートのリンクや鎖状のリンクも含みます。インジケータは大エリアの件数のみを表示します。

従来の「密な関係・疎な関係／平面・非平面」とホットスポットは、タグを含むグラフの分析として一覧の入口に残ります。平面性を確定できなかった全体は重ねて表示せず、「ホットスポット」と「ホットスポット外の未判定」に分けます。後者には疎な部分のほか、小ささなどで条件を満たさない部分も含みます。

「ホットスポット → 内部の素領域A・B → タグによる結合」の順に所属を辿れます。「結合領域」の一覧・件数には同じ親の内部の結合だけを含めます。異なる親領域をまたぐタグ接続は「他エリアとの接続」にタグと接続先の親名を示す参照として表示し、内部の結合領域として重複掲載しません。参照のグラフボタンは共有する領域間接続を開きます。素領域や接続の独立した大分類行、インジケータ下の補助件数は表示しません。親が重なる場合、素領域は親ごとの範囲で示され、全Vaultで重複のない分割とは限りません。

同じ接続の部分グラフボタンは、一覧で最初に登場した側だけに表示します。後から登場する側では、先のエリアを展開して接続の表示位置へ移動するボタンを表示します。ホットスポットと未判定に同じ接続がある場合は、先に表示されるホットスポット側が優先されます。

結合領域を展開すると、接続するタグと素領域ごとの該当ノートを確認できます。部分グラフでは素領域を色と［領域番号］で区別し、タグへの線は実際にタグを持つノートだけに表示します。複数のタグを介した関係を自動的に一つの巨大領域へ統合しません。部分グラフは最大90ノードで、超過時は省略を表示します。

素領域の展開先に示す平面性は、その直接リンクのグラフに対する判定です。結合領域には平面性の分類を付けません。標準グラフは大分類（平面・非平面・ホットスポット・その他の未判定）に基づいて着色し、縮約前の途中のノートも含めます。未判定部分の既定色は灰青で、設定から変更できます。複数分類で共有するノートは非平面、ホットスポット、平面、未判定の優先順で一色にします。タグだけでつながり素領域を持たないノート群は、今回の結合領域には含まれません。

## 導入と旧版からの移行

Obsidianを終了し、Vaultの `.obsidian/plugins/topology-keeper/` に配布物の `main.js`、`manifest.json`、`styles.css` を置いて起動します。コミュニティプラグイン画面で有効にしてください。

旧ローカル版のIDは `Topology-Keeper`、公開版は `topology-keeper` です。設定を引き継ぐ場合は、Obsidianを終了して旧プラグインフォルダと `data.json` をバックアップし、新しい小文字のIDに対応するフォルダへ `data.json` を移してください。大文字・小文字の区別がない環境では、一度仮のフォルダ名を経由して変更します。旧版と新版は同時に有効にしないでください。ノートや管理フォルダの移動は不要です。既存Vaultへの自動配置・ID移行は行いません。

## 外部ファイルと安全性

- 元ファイルは参照するだけで、取り込み時にVaultへコピーしません。メタノート・Base・サムネイルはVault内に作成します。
- 外部画像の埋め込み表示は既定でオフです。信頼できるVaultで、設定の「外部ファイル」から有効にしてください。元画像の自動オープン機能は廃止し、リストのファイル名クリックで元ファイルを開きます。
- ローカルの `file:` URLを扱います。ネットワークパスは対象外です。OSで開く際には実行ファイル・スクリプト等の主要形式も拒否しますが、あらゆる危険な文書を検知する機能ではありません。
- `source`には元ファイルの絶対パスが保存されます。Vault共有時にはユーザー名・フォルダ構成も共有され得ます。別PCへの同期では元ファイルの場所を修正する必要があります。サムネイルにも元画像の内容が含まれます。
- プラグイン本体に外部API送信・テレメトリーの実装はありません。OSの既定アプリで開いた文書の通信は、そのアプリの動作に従います。
- 画像は1枚32 MiBまで、元画像データのキャッシュは128 MiB・64件までです。これはデコード後の画像や画面全体のメモリ使用量の上限ではありません。
- 削除は確認後にObsidianのゴミ箱設定に従って行います。未解析ノート・取り込み中・未完了の取り込みがある間は削除を停止します。他から参照されるサムネイルも保護します。同期や同時編集の競合まで保証するものではないため、検証用Vaultとバックアップを使用してください。
- 自動削除候補は、識別情報を持つメタノート（旧版はUUID名とローカルsource）、UUID名のBase・WebPに限定します。管理フォルダ内に置かれた任意のファイルを一律に対象にはしません。

取り込みに失敗すると、作成・再利用したファイルのパスを `data.json` の復旧記録に保持します。コマンド「未完了の取り込みを復旧」または設定画面の「復旧」で、元ノートへのリンクとBase所属を補います。作成途中のメタノートの内容やサムネイルは確認してください。元ノートを移動した場合は元の場所へ戻してから復旧します。手動確認後は「記録だけ解除」でファイルを残して復旧記録を解除できます。

## 主な機能

- Vault内ノートのタグ提案
- 外部ファイルをノートへ関連付け、メタノートやサムネイルを作成
- Baseの作成・管理。取り込み用Baseは関連グループのメタノートを表示し、単体作成Baseは選択タグで絞り込む
- 関連付けたBase・ファイルの一覧表示、リンクのコピーと解除
- 孤立メタノート・サムネイル・Baseの検出と削除
- Vault外画像の埋め込み表示
- グラフの平面性・密度分析と、平面／ホットスポット／非平面の色分け

## Baseとメタノート

- 取り込み時に作るBaseはUUID名で保存し、所属グループに対応するメタノートを表示します。
- 単体作成BaseはUUID名で保存し、選択したタグだけを条件にします。複数タグはAND条件です。タグが未選択なら`filters`は設定しません。
- タグ条件は`file.hasTag("tag")`で評価し、候補にないタグも入力できます。

タグ提案では設定画面から、新規タグ候補に含めないストップワードを編集できます。1行に1語で入力します。

## エリア分析

### 平面性とクラトフスキーの定理

平面性は、辺を交差させずにグラフを描けるかという性質です。判定の背景となるクラトフスキーの定理に関連して、本プラグインではK₅・K₃,₃の構造や、その細分に必要な頂点の次数を調べます。次数1以下の除去と次数2の縮約で構造を簡略化してから検査します。平面性はノート内容の良し悪しを表すものではなく、領域分割後の判定でVault全体の平面性を保証するものでもありません。

### 判定と表示

分析対象はVault内ノートとタグから構築したグラフです。次数1以下の頂点を除き、次数2の頂点を抑制した単純グラフの2連結成分を、内部リンクが集中するまとまり（モジュラリティ）でさらに分割します。3頂点未満のまとまりや、内部の辺数が外部への辺数以下になる分割は採用しません。分割後に2連結成分を再抽出し、各エリアの平面性を判定します。同じ密度の領域同士でも、少数のリンクでつながる場合は別エリアになります。エリアをまたぐリンクは各エリア内の平面性判定には含めないため、グラフ全体の平面性を保証するものではありません。

- **非平面**: 頂点数が3以上で辺数が `3V−6` を超える、またはK₅／K₃,₃の構造を検出した領域。いずれも非平面であることの十分な証拠です。
- **平面**: K₅の細分に必要な次数4以上の頂点が5つ未満、かつK₃,₃の細分に必要な次数3以上の頂点が6つ未満の領域。この十分条件で平面と判定します。
- **ホットスポット**: 平面性を判定できない領域を、各ノードと1近傍の密度および隣接ノード間の密度差で分割したエリア。3ノード以上かつ密度25%以上のものを表示します。非平面を意味しません。

密度・平面性による4区分（密／疎 × 平面／非平面）は、グラフの状態を読むための目安であり、ノートの品質や分類の正誤を保証しません。境界候補と平均変化度は試験的な指標です。K₅／K₃,₃の探索上限は`plugin-settings.js`の`CONFIG.maxFindings`で定義します。

分類色は設定画面で変更できます。標準グラフを開くと、平面・ホットスポット・非平面ごとに色分けします。「エリア候補」インジケータから分析結果ウィンドウ、「孤立」インジケータから孤立ウィンドウを開きます。エリア候補には平面エリアも含みます。各エリアは折り畳み表示で、部分グラフボタンは常に表示します。

小窓・分析結果・孤立ウィンドウはドラッグ後の位置を保存し、次回表示・再起動時に復元します。分析結果・孤立ウィンドウの開閉状態も個別に保存します。各窓のヘッダーにある位置リセットボタンで、その窓を初期位置へ戻せます。設定画面の「位置をリセット」またはコマンド「小窓・詳細窓の位置をリセット」では各ウィンドウの位置を戻せます。部分グラフの初期サイズは最大680×500pxで、右下のハンドルから拡大・縮小できます。
部分グラフもタイトルバーをドラッグした位置を保存し、別エリアの表示時や再起動後に復元します。画面サイズが変わった場合は表示範囲内へ補正します。

## 設計上の規約

- 表示クラスは、必要な状態取得や操作をコールバックのオブジェクト（`api`）で受け取ります。Vault操作や分析計算と画面描画を分けます。
- `plugin-settings.js`の`FOLDERS`は複数モジュールで共有する参照です。再代入せず、値を変更するときは中身を更新します。
- Obsidianの標準グラフ色設定を反映するとき、コアプラグインの`disable`／`enable`は呼びません。保存した色設定で新しいグラフビューを開きます。
- コメントでは、データの入力元・形式と、返却・保存・書き込みの有無を明記します。推測した理由を事実として書かないようにします。

## ソースの検証・ビルド

Node.js 24を開発・テストに使用しています。Node.jsを導入し、`npm ci` で依存パッケージを取得してください。

- `npm test`: 分析・位置保存・削除保護・外部アクセス・復旧の自動テスト。
- `npm run check`: JavaScript構文、バージョンとmanifestの整合性確認。
- `npm run build`: minifyした一回ビルド。Vault配置・Git操作は行いません。
- `npm run package`: チェック・テスト・ビルド後、公開用リポジトリ内の `dist/<version>/` に配布3ファイルを作成します。ソースコピーは生成しません。

開発用バッチとローカル配置・監視用スクリプトは公開ソースに含めません。ビルド処理はステージ・コミット・プッシュを行いません。

## 作業時の確認

ビルド後はObsidianでプラグインを再読み込みし、変更した画面・操作を確認します。JavaScriptの構文確認には`node --check`を使えます。エリア判定ロジックの変更では、平面・非平面・ホットスポットの境界条件も確認してください。

エリア分析は約10秒の時間予算を超えた場合に中断し、前回の結果があれば対応するグラフと一緒に保持します。処理中のチェック地点で中断するため、厳密な実行時間上限ではありません。標準グラフの着色は非公開APIに依存し、利用できない場合は通知して終了します。

manifestと配布物の形式は[Obsidian公式manifest仕様](https://docs.obsidian.md/Reference/Manifest)と[公開手順](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin)に合わせています。IDの重複・審査通過・最小対応バージョンの実機互換性は未確認です。ライセンスは既存のpackage設定に合わせたISCです。

## 外部ファイルの名前変更・移動（0.28.0）

リスト行にマウスを重ねると、対象の名前を示すメニューが開き、対象行をハイライトします。外れると閉じます。「ファイル名の変更」「リンクをコピー」「リンクの削除」を選べます。ファイル名クリックは元ファイルを開く操作です。

リンクファイル見出しのフォルダーアイコンでは、対象をチェックボックスで選び、移動先を指定し、確認後にまとめて移動できます。同名ファイルは上書きせず、途中の失敗では停止して完了件数を表示します。名前変更・移動時は同じ外部ファイルを参照する管理用メタノートも更新します。処理中はファイルを一時的にコピーするため空き容量が必要です。異常終了からの自動復旧や、他アプリの参照更新には対応していません。

公開用リポジトリには開発用バッチ、ローカル配置・監視スクリプトを含めません。ソースからの確認・ビルドは Node.js を導入後、`npm ci`、`npm run package` で行えます。
