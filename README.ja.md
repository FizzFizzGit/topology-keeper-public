## エリア表示

英語UI対応として、設定画面・コマンド・メイン小窓・孤立・分析結果・部分グラフ・タグ提案・外部ファイル操作・取り込み復旧・整理時の確認と通知を日英辞書へ移行しました。Obsidianの表示言語が日本語なら日本語、それ以外は英語を使用します。言語変更後はプラグインを再読み込みしてください。画像読み込みなどの内部例外・開発ログには日本語が残る場合があります。英語UIとモーダルの表示は利用者確認済みですが、全画面・画面幅の網羅的な確認は未完了です。

「孤立」インジケータは通常ノートの孤立数と、孤立した管理データ（メタノート・サムネイル・Base）の合計です。通常ノートの判定はVault全体を対象にします。ほかの通常ノートとの直接リンク（入出力）も共通タグでの接続もないものを要確認として数えます。「タグのみで接続」は別表示です。設定の「孤立チェック対象外のフォルダ」に `未分類` などVault内の相対パスを指定すると、配下のサブフォルダも要確認の件数から外し、「孤立チェック対象外」に表示します。空欄なら許容フォルダは指定しません。ノートの移動・削除は行いません。従来のメタノート等の整理は孤立ウィンドウ内の「管理データの整理」に折り畳んで残しています。

分析ウィンドウのタイトルバーから距離エリアを再計算できます。エリアを展開すると、直接リンクでつながるノート群を「素領域」、共通タグでつながる素領域や単独ノートを「結合領域」として確認できます。親エリアをまたぐタグ接続は「他エリアとの接続」に表示します。同じ接続が複数箇所に出るときは、最初の表示へ移動できます。

分析結果と最短ホップ表は設定データに保存し、再起動後も使います。接続が変わった場合は、影響を受ける始点の距離を再探索します。メインウィンドウの「エリア」は親エリアの件数です。

部分グラフではノートやタグの接続を確認できます。独立ウィンドウでは位置とサイズを記憶します。分析ウィンドウから標準グラフを開くと、結合領域の色が所属ノートに反映されます。

## 導入と旧版からの移行

Obsidianを終了し、Vaultの `.obsidian/plugins/topology-keeper/` に配布物の `main.js`、`manifest.json`、`styles.css` を置いて起動します。コミュニティプラグイン画面で有効にしてください。

旧ローカル版のIDは `Topology-Keeper`、公開版は `topology-keeper` です。設定を引き継ぐ場合は、Obsidianを終了して旧プラグインフォルダと `data.json` をバックアップし、新しい小文字のIDに対応するフォルダへ `data.json` を移してください。大文字・小文字の区別がない環境では、一度仮のフォルダ名を経由して変更します。旧版と新版は同時に有効にしないでください。ノートや管理フォルダの移動は不要です。既存Vaultへの自動配置・ID移行は行いません。

## 外部ファイルと安全性

- 元ファイルは参照するだけで、取り込み時にVaultへコピーしません。メタノート・Base・サムネイルはVault内に作成します。
- 外部画像の埋め込み表示は既定でオフです。信頼できるVaultで、設定の「外部ファイル」から有効にしてください。元画像の自動オープン機能は廃止し、リストのファイル名クリックで元ファイルを開きます。
- ローカルの `file:` URLを扱います。ネットワークパスは対象外です。OSで開く際には実行ファイル・スクリプト等の主要形式も拒否しますが、あらゆる危険な文書を検知する機能ではありません。
- `source`には元ファイルの絶対パスが保存されます。Vault共有時にはユーザー名・フォルダ構成も共有され得ます。別PCへの同期では元ファイルの場所を修正する必要があります。サムネイルにも元画像の内容が含まれます。
- テレメトリーや外部の撮影サービスは使いません。Webサムネイルの撮影時は指定ページとそのリソースへ通信します。OSの既定アプリで開いた文書の通信は、そのアプリの動作に従います。
- 画像は1枚32 MiBまで、元画像データのキャッシュは128 MiB・64件までです。これはデコード後の画像や画面全体のメモリ使用量の上限ではありません。
- 削除は確認後にObsidianのゴミ箱設定に従って行います。未解析ノート・取り込み中・未完了の取り込みがある間は削除を停止します。他から参照されるサムネイルも保護します。同期や同時編集の競合まで保証するものではないため、検証用Vaultとバックアップを使用してください。
- 整理候補は、メタノート専用フォルダ内のMarkdownノート、UUID名のBase・WebPと、生成記録のあるUUID名PNGです。メタノートの識別プロパティは不要です。参照中のデータと、タグの付いたメタノートは候補から外します。

取り込みに失敗すると、作成・再利用したファイルのパスを `data.json` の復旧記録に保持します。コマンド「未完了の取り込みを復旧」または設定画面の「復旧」で、元ノートへのリンクとBase所属を補います。作成途中のメタノートの内容やサムネイルは確認してください。元ノートを移動した場合は元の場所へ戻してから復旧します。手動確認後は「記録だけ解除」でファイルを残して復旧記録を解除できます。

## 主な機能

設定の「ウィンドウ共通」でメイン・分析・孤立ウィンドウの文字サイズ、幅、高さの下限・上限を指定できます。独立窓の幅は既定280pxで、狭い画面では画面幅に収めます。高さは内容に合わせて伸縮します。「ウィンドウの表示先」では、メイン・分析・孤立・部分グラフごとに独立ウィンドウ、左サイドパネル、右サイドパネルを選べます。

- Vault内ノートのタグ提案
- 外部ファイルをノートへ関連付け、メタノートやサムネイルを作成
- Baseの作成・管理。取り込み用Baseは関連グループのメタノートを表示し、単体作成Baseは選択タグで絞り込む
- 関連付けたBase・ファイルの一覧表示、リンクのコピーと解除
- 孤立メタノート・サムネイル・Baseの検出と削除
- Vault外画像の埋め込み表示
- 距離エリアの分析と、結合領域の平均接続数・平面性による色分け

## Webページへのサムネイル付きリンク（試作・デスクトップ専用）

通常のMarkdownノートを開き、メインウィンドウの地球アイコンからURLを入力できます。URL未選択なら開始時のカーソル位置へ挿入します。本文のHTTP(S)のURLまたはMarkdownリンクを選び、コマンド「選択URLをサムネイル付きリンクにする」を実行する方法もあります。URLだけの行なら、その行にカーソルを置いて実行できます。モーダルではURLを編集でき、撮影前に幅（64〜1024px、既定256px）と「画像内のタイトル枠にページタイトルを描き込む」を指定できます。ページ上部を撮影し、プレビューで「保存して挿入」を押すと、画像下部に半透明のタイトル枠を重ねたPNGを保存し、クリックで元ページを開く画像リンクを、行頭に「> 」を付けた引用ブロックとして本文へ挿入します。タイトルは画像へ直接描き込み、別の文字列リンクは挿入しません。タイトル枠はオフにもできます。

画像は指定幅へ縮小し、管理サムネイルフォルダへ UUID.png として保存します。Vault全体で同名ファイルがないことを確認し、本文リンクにはファイル名だけを使います。生成パスと指定幅はdata.jsonへ記録し、孤立判定と表示へ使います。外部の撮影サービスは使わず、実行時に指定ページとそのページが読み込むリソースへ通信します。一時セッションを使うため、普段のブラウザのログイン状態は引き継ぎません。ログイン画面やCookie確認が写る場合があり、非表示撮影用のオフスクリーン描画を使い、画像・フォント・描画フレームの準備を待ってから撮影します。白紙・単色画像や不完全なサイズは再試行し、取得できなければ保存せず終了します。25秒でタイムアウトします。対応するElectron機能が使えない環境では通知して終了します。実Obsidianでの撮影確認は未完了です。

キャンセル時は画像を保存しません。撮影中に元ノートが変わった場合は挿入を止めます。挿入した画像は本文のリンクを消しても残りますが、参照がなくなると「管理データの整理」の孤立サムネイル候補へ表示します。確認後にゴミ箱へ移せます。他ノートの本文・埋め込み・coverから参照されている間と、Webサムネイル作成中は削除を保護します。

## Baseとメタノート

- 取り込み時に作るBaseはUUID名で保存し、所属グループに対応するメタノートを表示します。
- 単体作成BaseはUUID名で保存し、選択したタグだけを条件にします。複数タグはAND条件です。タグが未選択なら`filters`は設定しません。
- タグ条件は`file.hasTag("tag")`で評価し、候補にないタグも入力できます。

タグ提案では設定画面から、新規タグ候補に含めないストップワードを編集できます。1行に1語で入力します。

## エリア分析

ノートとタグを頂点、ノート間リンクとタグ付与を辺として、ワーシャル・フロイド法で最短ホップ数を求めます。近傍同士の重なりから境界票を集め、分割票率が暫定値の2.5%を超えた辺でエリアを分けます。分析上限は256頂点です。

素領域と結合領域の平面性は、領域内の接続から判定します。辺数の条件と、クラトフスキーの定理に基づくK₅・K₃,₃の検査を行い、必要に応じて辺の巡回順や閉路の左右の配置条件を調べます。結合領域は、ノートとタグを含む1頂点あたりの平均接続数が暫定値の3.5本以上なら「密」と判定します。

結合領域の既定色は、密・平面がオレンジ、疎・平面が青、密・非平面が赤、疎・非平面が灰色です。判定不能は色なしです。色は設定から変更できます。標準グラフで所属が重なるノートには、判定済みで所属ノート数が最も多い結合領域の色を使います。

判定の手順と保存データは[機能仕様書](docs/specification/SPECIFICATION.ja.md)を参照してください。

## 設計上の規約

- 表示クラスは、必要な状態取得や操作をコールバックのオブジェクト（`api`）で受け取ります。Vault操作や分析計算と画面描画を分けます。
- 管理フォルダの正本は`state.folders`です。変更とリセットは参照を維持し、実行用と保存用の二重管理を行いません。
- Obsidianの標準グラフ色設定を反映するとき、コアプラグインの`disable`／`enable`は呼びません。保存した色設定で新しいグラフビューを開きます。
- コメントでは、データの入力元・形式と、返却・保存・書き込みの有無を明記します。推測した理由を事実として書かないようにします。

## ソースの検証・ビルド

Node.js 24を開発・テストに使用しています。Node.jsを導入し、`npm ci` で依存パッケージを取得してください。

- `npm test`: 分析・位置保存・削除保護・外部アクセス・復旧の自動テスト。
- `npm run check`: JavaScript構文、バージョンとmanifestの整合性確認。
- `npm run build`: 開発側は`PLUGIN_DIR`へ直接ビルド。未指定時はエラー。公開側は`dist/<version>/`へ直接生成。Git操作は行いません。
- `npm run package`: チェック・テスト・ビルド後、公開用リポジトリ内の `dist/<version>/` に配布3ファイルを作成します。ソースコピーは生成しません。

開発用バッチとローカル配置・監視用スクリプトは公開ソースに含めません。ビルド処理はステージ・コミット・プッシュを行いません。

## 作業時の確認

ビルド後はObsidianでプラグインを再読み込みし、変更した画面・操作を確認します。JavaScriptの構文確認には`node --check`を使えます。エリア判定ロジックの変更では、距離エリアの分割と平面性・平均接続数の判定も確認してください。

エリア分析は約10秒の時間予算を超えた場合に中断し、前回の結果があれば対応するグラフと一緒に保持します。処理中のチェック地点で中断するため、厳密な実行時間上限ではありません。標準グラフの着色は非公開APIに依存し、利用できない場合は通知して終了します。

manifestと配布物の形式は[Obsidian公式manifest仕様](https://docs.obsidian.md/Reference/Manifest)と[公開手順](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin)に合わせています。IDの重複・審査通過・最小対応バージョンの実機互換性は未確認です。ライセンスは既存のpackage設定に合わせたISCです。

## 外部ファイルの名前変更・移動（0.28.0）

リスト行にマウスを重ねると、対象の名前を示すメニューが開き、対象行をハイライトします。外れると閉じます。「ファイル名の変更」「リンクをコピー」「リンクの削除」を選べます。ファイル名クリックは元ファイルを開く操作です。

リンクファイル見出しのフォルダーアイコンでは、対象をチェックボックスで選び、移動先を指定し、確認後にまとめて移動できます。同名ファイルは上書きせず、途中の失敗では停止して完了件数を表示します。名前変更・移動時は同じ外部ファイルを参照する管理用メタノートも更新します。処理中はファイルを一時的にコピーするため空き容量が必要です。異常終了からの自動復旧や、他アプリの参照更新には対応していません。

公開用リポジトリには開発用バッチ、ローカル配置・監視スクリプトを含めません。ソースからの確認・ビルドは Node.js を導入後、`npm ci`、`npm run package` で行えます。
