# 開発手順とテストの方針

## 配置

| 場所 | 内容 |
| --- | --- |
| ルート | README、ライセンス、npm・Obsidian・Gitの設定、バッチの入口 |
| `src/` | プラグインの起動口 `main.js`、共通CSS、機能別ソース |
| `../build/` | ビルド・配置・配布・検証のスクリプト |
| `docs/` | 仕様・設計・開発記録 |
| `docs/development/measurements/` | ベンチマークのJSONL生データ |
| `output/` | PDF等の成果物と検証ログ。Git管理対象外 |
| `tests/` | 自動テストとその補助 |

## ビルドと配置

実装はワークスペース直下の `build/` に集約しています。ルートから `build\build-dev.bat` を実行すると開発用Vaultへ配置し、`build\build-dist.bat` は公開側のソースから配布アセットを生成します。両側の `npm test` は共通ランナーを使い、実行元リポジトリのテストを実行します。

- `npm run build`／`npm run deploy`：`PLUGIN_DIR`へ直接ビルドし、成功時にCSSとmanifestを同期する。
- `npm run dev`：同じ配置先へ直接ビルドし、JS・CSS・manifestの変更を監視する。
- `build.bat`／`dev.bat`：`env.local.bat`等から環境を読み、上記のビルド／監視を実行する。
- 配置先未指定時はエラーにする。ルートや`build/`へ代替出力しない。
- 配布用は`node ../build/build-release.mjs`で`dist/<version>/`へ三ファイルを直接生成する。
- 公開リポジトリの`npm run build`は、この配布用ビルドを呼ぶ。

シェルからnpmコマンドを使う場合は`PLUGIN_DIR`を環境変数として設定する。
バッチの入口は`env.local.bat`を読み込む。開発・配布のいずれも中間のローカルJSは作らない。

`src/styles.css`は編集するソース。配置先・配布先へ`styles.css`として直接コピーし、リポジトリ直下に中間コピーは作らない。
CSSとmanifestはビルド成功後に同期する。配置先の`data.json`はコピー・上書きしない。
別プラグインのmanifestがある場合はビルド前に拒否し、既存のローカルIDの大文字・小文字は維持する。
ビルド失敗時は配置先の既存JSを維持する。三ファイルを一括で置き換えるトランザクションではない。

## テストを残す判断

現行テストを機能別に点検した。ファイル数や本数だけを理由には削除しない。

| 分類 | 保証すること | 方針 |
| --- | --- | --- |
| 分析・タグ提案 | 接続・所属・評価・キャッシュの正しさ | 残す。異なる層のテストを同じものと扱わない |
| 削除・保存・取り込み・撮影 | 参照保護、競合、中断、失敗時のデータ保持 | 残す。破損や誤削除を防ぐ主要な保証 |
| UI・窓・説明 | 折り畳み、操作位置、解除、日英表示、矢印 | 残す。純粋な計算だけでは確認できない |
| 配置・公開 | 配置先の検証、設定保持、公開対象の制限 | 残す。実Vaultを使わず一時フォルダで確認 |
| 旧形式専用 | 廃止した互換機能の保証 | 現行仕様に置換または削除済み |
| 同じ条件の重複 | 旧キーを無視すること等 | 専用テストへ集約。窓座標のテストに重ねて持たない |

テスト用の模擬DOM・Electronは実機そのものではない。
外観・テーマ・実描画・ホストの安定性はObsidianでも確認する。
実行は`npm test`、構文等の確認は`npm run check`。

## 公開用ソースだけでの通し検証

`npm run validate:public`で、実際と共通の公開用変換を空の一時フォルダへ適用し、
公開対象だけでpackageコマンド（構文確認・テスト・配布先への直接ビルド）を実行する。
インストール済み依存を独立コピーしてlockfileと照合するが、新規npm ciの取得確認とは区別する。
実際の公開リポジトリ・Vaultへの書き込みやpushは行わない。
結果は`output/logs/public-validation.json`と同名の`.log`へ保存する。
