# タグの構造的な役割の自動評価（0.29.0 開発中）

日記などのタグを名前で判定したり、除外リストへ手動登録したりせず、付与先ノートの独立した関係から評価する。話題タグか形式タグかを意味的に断定する機能ではない。

## 根拠

- 候補タグ自身は共通タグの評価から除く。
- 他の共通タグは、全対象ノートに対する出現頻度で重み付けする。重みは `log(対象ノート数 / タグ付与ノート数)`。全ノートに付くタグの重みは0。
- 付与先ノートの全ペアについて、他タグの重み付き共通量／和集合量を集計する。ノートペア自体を列挙せず、共起件数から算出する。
- 候補タグの付与先同士の直接リンク密度と、直接リンクだけで作った連結成分への集中度も計算する。タグが作った領域を集中度の根拠にせず、循環を避ける。

## 暫定ルール

付与先が3ノート以上で、半数以上に識別力のある他タグがある、または付与先同士に直接リンクがある場合に評価する。それ以外は材料不足として重みを維持する。

構造スコアは `0.75 × max(共通タグ類似度, 直接リンク密度) + 0.25 × 集中度`。集中度は `(最大連結成分内の付与先数 − 1) / (付与先数 − 1)`。
スコア0.3未満を横断的な接続の候補とし、構造分割の辺の重みを `0.2 + 0.8 × スコア` に弱める。それ以外は重み1。しきい値と配分は `src/tag-role.js` に集約した仮説であり、精度保証や確率ではない。

## 適用範囲

重みは構造分割のまとまりを決める部分に適用する。縮約辺も元のタグを追跡して重みに反映する。実際のタグ・リンクは削除せず、結合領域と部分グラフには残す。平面性検査と表示密度は実際の無重みグラフに基づくため、重みを下げたこと自体で平面と判定することはない。ただし分割範囲が変われば、各範囲の判定結果は変わり得る。

結合領域の展開先に、役割の推定、共通タグ類似度、直接リンク密度、分布するリンク成分数、適用した重みを表示する。本文の読み込み、外部API、設定データへのタグ名の固定登録は行わない。

## 検証と制限

### 共通タグによる過剰な統合への対策

縮約前に、横断的と推定したタグを一時的に外し、閉路を持つ2連結成分を探す。ノートを2件以上含む成分が複数あり、同じ横断タグが別々のノートを介してそれらを結ぶとき、成分ごとに分析範囲を分ける。話題をまたぐ日記は複数の範囲に含まれ得る。各範囲の内部では元のタグ辺を戻し、範囲をまたぐタグの関係は元のグラフから表示する。

各分析範囲では、タグを通らないノート間リンクでも構造分割を試みる。3ノート以上のまとまりが複数あり、各まとまりの内部次数合計が外部次数合計を上回る場合、その分割を優先する。共有タグは各領域に残し、領域間の関係を結合領域として表示する。タグ由来の縮約辺は直接リンクの根拠に含めない。全タグをこの分割で扱えない場合は従来の重み付き分割に戻す。

3つの直接リンク群が少数のリンクでつながった例で、共通タグ1つの追加により3領域が1領域になる現象を再現した。タグが強い関係と評価される場合も3領域を保ち、3領域を横断する結合を保持する回帰テストを追加した。この対策は、直接リンクによる独立したまとまりを確認できる場合に限る。

日記型の広い接続と直接リンクの密な話題群、材料不足、全体共通タグ、名前変更、キャンセル、重みの変更による構造分割、横断関係の保持を自動確認する。意味のある領域横断タグも弱く評価し得るため、自動除外はしない。

実Vaultでの妥当性は未確認。タグが少ないVaultでは材料不足が増える。直接リンクの連結成分は直接的な関係の近さそのものではない。実例を比較して、根拠・配分・しきい値を調整する。
