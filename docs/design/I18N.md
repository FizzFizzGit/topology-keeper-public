# UI辞書：0.29.0 第1段階

## 0.30.0向けの追加部分

「ウィンドウ共通」の文字サイズ・幅・高さの下限・上限・既定幅280pxと高さ下限280px、インフォの種類別見出し、
番号を省いた素領域表示に日英を用意した。説明文は `section-help.js` で選び、
`info-content.js` が標準DOMへ描画する。`info-popover.js` は言語に依存しない。
独立デモも日英を切り替えられ、閉じるボタンのアクセシブル名は `closeLabel` で渡す。
設定定義から動的に参照する翻訳キーと、インフォ各種の英語も自動検証する。
コードの日本語コメントは再利用時の説明として維持し、表示文言の翻訳とは分けて扱う。

## 構成

- `src/ui-dictionary.js`、`src/ui-window-dictionary.js`、`src/ui-file-dictionary.js`：安定したキーに対する日本語・英語の文言。保存キー・CSSクラス・利用者入力は辞書に入れない。
- `src/i18n-core.js`：言語の正規化、英語フォールバック、名前付き差し込み、単数形の選択。
- `src/i18n.js`：Obsidianの表示言語に追従する `t(key, values)`。
- `src/ui-constants.js`：既存の `UI_TEXT` の読み取り口を維持し、共通操作語を翻訳する。

言語取得は公開API `getLanguage()` を使用する。公式API定義では1.8.7以降で利用可能で、プラグインの宣言する最低版1.9.0に含まれる：[Obsidian API定義](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)。日本語（ja、ja-JP等）は日本語、それ以外は英語。コマンドは登録時の名前になるため、言語変更後はプラグインを再読み込みする。

## 現在の移行範囲

設定画面の見出し・説明・ボタン・入力エラー・通知、6コマンドの表示名、`UI_TEXT` の共通操作語を移行した。コマンドID、保存済み設定、フォルダ名、ノート名、入力されたストップワードは変更しない。

第2段階としてメイン小窓・孤立ウィンドウ・分析結果の見出し、分類名、件数、説明、タグ評価、接続操作も移行した。親領域の表示名は描画時に翻訳し、分析データと利用者のノート名は変更しない。インジケータは英語の長いラベルを枠内で折り返し、内容に合わせて高さを変える。

第3段階として部分グラフの操作・凡例・説明、関連ファイル一覧と編集メニュー、名前変更・移動・Base作成、取り込み・復旧、タグ提案、管理データ整理の確認、分析・標準グラフ着色の通知も移行した。ファイル名・タグ名・入力したビュー名は翻訳しない。失敗時のパスと元エラーは翻訳文へそのまま差し込む。部分グラフの英語見出しには折り返しを許可した。

主要画面と操作の移行は完了したが、画像読み込みなどの内部例外や開発ログには日本語が残る場合がある。英語本文に対するタグ提案の品質改善はこの作業に含まない。実Obsidianでの全画面・失敗経路の言語漏れとレイアウト確認は未実施。

## 追加方法

表示用途を表すキーを追加し、両言語を同時に記入する。件数などは文字列を連結せず `{count}`、`{path}` のような名前付き引数を使う。

```js
t('settings.pendingDesc', { path: pendingImport.mainNotePath });
t('count.notes', { count: notes.length });
```

英語でcountが1の場合は `.one` キーを優先する。欠落した言語キーは英語へ、存在しないキーはキー文字列へフォールバックする。渡していない引数はプレースホルダを維持する。値は再展開せず、ユーザーのパスに含まれる波括弧やドル記号もそのまま表示する。出力はテキストとして使用し、HTMLへ挿入しない。

辞書キー・差し込み引数の一致、言語取得、フォールバック、件数、ユーザー値の維持、日英設定画面を自動確認している。実Obsidianでの英語の折り返し・ボタン幅などの目視確認は未実施。
