## 1. 目的と対象環境

ノート間のリンクとタグから構造を把握し、外部ファイルの関連付けと管理データの整理を支援します。
分析結果は見直すための材料であり、ノートの内容・分類の正しさを断定するものではありません。

- Obsidianデスクトップ用。manifestの最小対応バージョン指定は1.9.0です。
- 主な開発・利用確認環境はWindowsです。他OS・最小対応版での動作保証を意味しません。
- Obsidianの表示言語が日本語なら日本語、それ以外は英語を使います。
- 本文解析によるタグ提案はローカルで処理します。Web撮影では対象サイトへ通信します。

## 2. 用語とデータの関係

| 用語 | 意味 |
| --- | --- |
| 通常ノート | 設定された管理フォルダ外にあるMarkdownノート |
| 管理フォルダ | プラグインの生成データを置く専用フォルダ。配下も管理対象とする |
| メタノート | Vault外のファイルを表すMarkdownノート。元ファイルそのものではない |
| サムネイル | 表示用の縮小画像。メタノート用WebPと、Web撮影用PNGがある |
| Base | Obsidianの`.base`ファイル。メタノートのグループやタグ条件で一覧を表示する |
| エリア | リンク・タグの構造から得られた領域。実生活上の分類としては候補である |
| 素領域 | 親エリア内で、タグを経由しない直接リンクでつながるノート群 |
| 結合領域 | 同じ親エリア内の素領域や単独ノートを共通タグで結び付けた関係 |

既定の管理フォルダは次のとおりです。名前は設定で変更できます。

| フォルダ | 内容 |
| --- | --- |
| `_meta` | メタノート |
| `_thumbs` | 生成したサムネイル |
| `_bases` | 生成したBase |

メタフォルダはメタノート専用です。所属によって判定し、`topologyKeeper: true`は要求も新規付与もしません。
既存の同プロパティを削除する移行処理はなく、手動で除去できます。

### 2.1 参照関係

```text
通常ノート
  ├─ links → メタノート → source → Vault外の元ファイル
  │                    └─ cover → WebPサムネイル（画像の場合）
  ├─ links → Base → 条件に合うメタノート等を表示
  └─ 本文の画像リンク → Web撮影PNG → クリック先は元のWebページ
```

Web撮影ではメタノートを作りません。画像でない外部ファイルや生成失敗の場合はサムネイルがありません。
したがって、メタノート・サムネイル・Baseの個数は一致する必要がありません。

## 3. 画面と操作

| 画面 | 主な役割・操作 |
| --- | --- |
| メイン窓 | 孤立合計数とエリア数、関連する外部ファイル・Base、取り込み・タグ提案・Web撮影・Base作成、設定への入口 |
| 孤立窓 | 通常ノートの孤立一覧と、孤立した管理データの整理。更新ボタンは孤立判定だけを実行 |
| 分析窓 | エリアの分類、内部の素領域・結合領域・他エリアとの接続。更新ボタンはエリア分析だけを実行 |
| 部分グラフ | 選択エリアのノード・辺・方向を表示し、配置・パン・ズームを操作 |
| 各モーダル | URL入力、撮影確認、タグ選択、ファイル名変更など、個別操作の入力・確認 |

メイン窓には再計算ボタンを置きません。タイトルバーの歯車から設定を開けます。
メイン・孤立・分析窓は、クリック／フォーカスした窓を前面へ移します。
説明はインフォアイコン内に集め、見出し・段落・箇条書きなどで表示します。
説明の表示機能はMarkdownの一部に似た書式であり、任意のMarkdownやHTMLの全面対応ではありません。

### 3.1 窓の寸法

メイン・孤立・分析窓には共通設定を適用します。

- 文字サイズは既定100%、設定範囲80〜140%。説明ポップオーバーにも反映します。
- 幅は共通設定の指定値に固定し、既定は280pxです。画面が狭い場合は画面幅に収めます。
- 高さは内容に応じて伸縮し、既定は下限280px・上限は画面の高さです。
- 下限は「なし」を選べます。上限と画面内への収まりを優先します。
- 高さ上限を超えた内容は本文部分をスクロールします。
- 設定変更は即時反映・保存し、そのためだけに分析を実行しません。

部分グラフ窓とモーダルは共通寸法設定の対象外です。

### 3.2 部分グラフ

- ノートをクリックすると編集用タブで開きます。ドラッグでは配置を変更します。
- 初期の座標枠への押し戻しは行いません。端でドラッグを続けると視点を移動します。
- 空白のドラッグでパン、ホイールや＋／−でズームします。
- 「全体表示」は、移動したノードとラベルを含む現在の配置に表示を合わせます。
- 実ノート間のリンクには、リンク元からリンク先へ矢印を描きます。相互リンクは両向きです。
- タグの所属線・縮約された辺には向きを付けません。無向の分析結果から方向を推測せず、解決済みの元リンクを使います。
- 矢印位置は表示円の半径・線幅・余白から算出します。操作用の大きな円は透明です。
- 描画順は辺、矢印、ノード・文字の順です。文字の可読性を優先します。
- 中核の表示上限は既定90ノードで、設定の「グラフ表示」で30〜1,200の候補から選べます。上限を超える場合、エリア内の辺を使って芯に近い順に表示します。同じ距離では次数の高いノードを優先します。必要に応じた周辺ノードは最大35で、選択方法によっては周辺を加えません。
- 窓の位置・サイズを保存します。ノードの配置・パン・ズームは保存せず、グラフ再生成時に初期化します。

## 4. エリア分析

管理フォルダを除いたノートとタグを対象に、分析用の無向グラフを作ります。
リンクの入出力方向は分析上の辺では区別せず、部分グラフの矢印表示時に元データから取り戻します。

平面性のエリア候補は平面、非平面、未判定に分けます。未判定部分は低密度・小規模・境界部分に分けます。
ここでの平面性はグラフの性質であり、画面上で線が交差して見えるかだけでは決まりません。
上限や時間制限もあるため、「非平面が見つからない」をすべてのグラフの平面性の証明として扱いません。

親エリア内の直接リンク群を素領域として表示し、二ノートの接続や鎖状の接続も含めます。
距離エリア内の素領域には、直接リンクで所属ノートまでの合計ホップ数が最小になるノートの名前を付けます。
分析表示は現行の親エリアを持つ階層モデルだけを扱い、旧形式の独立したエリア一覧への互換表示は行いません。
素領域は親ごとの範囲に属し、全Vaultを重複なく分割したものとは限りません。通し番号は付けません。
素領域や結合領域がない場合、その項目は表示しません。

同じ親の内部で共通タグが複数の素領域や単独ノートをつないでいる場合、その関係を結合領域として表示します。

分析窓の「エリア」では、全体グラフを手動で分析できます。見出しの下に結果を常に表示し、個別エリアを展開すると内訳を確認できます。最短ホップ数から近傍を広げ、境界票率が暫定値の2.5%を超える接続を除いた連結成分を表示します。各成分の素領域と結合領域は、分割後に残った接続で求めます。領域間のタグ関係は元のグラフから表示します。

256頂点、または連結成分内のノート対数と頂点・辺数から見積もる作業量の目安を超えた場合は、利用者が分析窓で開始を確認します。距離分析の頂点数と時間に固定上限はありません。計算中は処理段階を表示し、進捗バーの横のボタンで中止できます。計算が失敗した場合や中止した場合は、前回結果と保存済み距離表を保持します。距離表があり、グラフの頂点・辺に変更がない場合は前回結果をそのまま使います。

計算に成功すると、表示結果、隣接データ、全頂点間の最短ホップ表、計算日時を圧縮して設定データに保存します。圧縮前の保存データが32 MiBを超える場合、今回の結果は実行中のセッションで参照できます。初回はワーシャル・フロイド法で距離表を作ります。再計算では、追加・削除された辺で距離が変わり得る始点と新しい頂点から幅優先探索し、残りの行は前回の表を使います。境界票とエリアの内訳は更新した距離表から求め直します。前回結果は起動時に復元され、再計算の途中や失敗時にも表示に残ります。距離エリアの結果がある間は分析窓を距離エリア表示に切り替えます。

境界票の作業量から約1秒以上と見込まれる場合は、開始時から進捗バーを表示します。見積もりが短くても、計算が1秒続けば処理の区切りで表示します。境界票の段階では確認済みのノート対の割合を表示し、最短ホップとエリア構築・診断の段階では処理中であることを示します。

コマンドパレットの「保存済みの距離分析を削除」で、前回の距離エリアと距離表を消去できます。次に分析を実行すると、最短ホップ表を初回と同じ手順で作成します。

分析窓から標準グラフを開くと、前回のプラグインの色グループを結合領域の4区分の色に更新します。複数の結合領域に属するノートは、平面性が判定済みの領域のうち、所属ノート数が最も多い領域の色を使います。

距離エリアの見出しには、分割後に残った接続で所属ノートまでの合計ホップ数が最小になるノートまたはタグを使います。同点ならタグを優先します。距離エリアの背景は設定の未判定色です。素領域と結合領域は、部分グラフに表示する実際の接続から平面性を診断します。結合領域の診断には、所属ノートが親エリア内で持つタグ辺も含めます。簡易検査で確定しない成分は辺の巡回順を調べ、組み合わせ数が処理上限を超える場合は左・右平面性判定に切り替えます。結合領域はタグ辺を含む平均接続数（辺数の2倍を頂点数で割った値）を求めます。暫定基準の3.5本以上を「密」とし、平面性と組み合わせた4区分で色分けします。結合領域の既定色は、密・平面がオレンジ、疎・平面が青、密・非平面が赤、疎・非平面が灰色です。判定不能は色なしです。4区分の色は設定で個別に変更できます。平面性の診断結果は展開先に表示します。
異なる親をまたぐ接続は「他エリアとの接続」として扱い、内部の結合件数に混ぜません。
同じ接続が繰り返し現れる場合、後の表示は最初の表示位置へ移動するボタンに置き換えます。
展開状態はビューの再描画をまたいで保持します。

タグの役割は、他タグとの重なりや直接リンクでのまとまりから評価します。
候補タグ自身を根拠に使わず、まとまりの弱い横断的なタグは領域分割への影響を弱めます。
根拠不足の場合は重みを維持します。単語の意味を理解して種別を断定する機能ではありません。

## 5. 孤立判定と削除

**「孤立」は、通常ノートに対しては見直しの候補、管理データに対しては整理の候補です。**
メイン窓の件数は両者の合計です。孤立件数があっても削除ボタンがあるとは限りません。

### 5.1 通常ノート

| 条件 | 表示 |
| --- | --- |
| 他の通常ノートとの直接リンクがある（入出力のどちらでもよい） | 孤立一覧に含めない |
| 直接リンクはなく、設定された対象外フォルダ配下にある | 孤立チェック対象外 |
| 直接リンクはなく、他の通常ノートと共通タグがある | タグのみで接続 |
| 上記のいずれにも当てはまらない | 要確認の孤立ノート |

自己リンクは接続に数えません。本文リンクと`links`プロパティの内部リンクを確認します。
管理データだけにリンクしていても、通常ノート同士の接続にはなりません。
自分にだけ付いているタグも、他ノートへの接続にはなりません。
通常ノートの一覧からはノートを開けますが、削除ボタンは提供しません。

### 5.2 管理データ

| 対象 | 孤立候補の条件 |
| --- | --- |
| メタノート | メタフォルダ内にあり、他から参照されず、ノート自身にタグがない |
| WebPサムネイル | サムネイルフォルダ内のUUID名WebPで、参照されていない |
| Web撮影PNG | サムネイルフォルダ内のUUID名PNGで、生成記録があり、参照されていない |
| Base | Baseフォルダ内のUUID名Baseで、他から参照されていない |

サムネイルは解決済みリンク、本文の埋め込み、メタノート等の`cover`からの参照を確認します。
任意のPNGは生成記録がなければ整理対象にしません。
メタノートの場合、タグが一つでもあれば、他と共通していなくても削除候補から外します。
このタグの扱いは通常ノートの孤立判定とは異なります。

### 5.3 削除操作

- 「管理データを削除」は、孤立メタノートと単独サムネイルを対象とします。
- Baseには別の一括削除・個別削除があります。名称上の「管理データ」とボタン対象の範囲にはこの違いがあります。
- 確認後、Obsidianのゴミ箱設定に従って処理します。自動で削除はしません。
- メタノートを削除すると、対応サムネイルも孤立していて共有されていなければ削除します。
- 表示済みの一覧だけで削除せず、実行時に参照を再確認します。
- 未解析ノート、ファイル取り込み中、Webサムネイル作成中、未完了の取り込み記録がある場合は削除を止めます。

## 6. 外部ファイル管理

通常ノートにVault外のローカルファイルを関連付けます。
取り込みでは元ファイルをVaultへコピーせず、メタノート等を作って参照します。
元ファイルの場所は`file:` URLとして保存します。

メタノートの主なプロパティは次のとおりです。

| キー | 内容 |
| --- | --- |
| `source` | 元ファイルのローカル絶対パスを表すfile URL |
| `title` | 元ファイル名 |
| `base` | 所属するBaseのファイル名の配列 |
| `cover` | サムネイルへの内部リンク。画像が作れた場合のみ |

通常ノートの`links`プロパティには、関連付けるメタノートやBaseへの内部リンクを追加します。
画像は長辺256pxを上限としてWebPサムネイルを作ります。元ファイル・メタノート・画像は別データです。
関連一覧から元ファイルを開く、内部リンクをコピーする、関連を解除するなどの操作ができます。
ファイル名変更・移動は明示的な操作として扱います。取り込み時の参照登録とは区別します。

取り込み途中に失敗した場合は`pendingImport`へ作成・再利用したファイル等の記録を残します。
「未完了の取り込みを復旧」で元ノートへの接続を補い、成功後に記録を解除します。
「記録だけ解除」は生成ファイルを消しません。自動的な完全ロールバックではありません。

取り込み用Baseは所属グループのメタノートを表示します。
単体作成Baseは指定タグで絞り込み、複数タグはAND条件、未指定ならタグの絞り込みを設定しません。

## 7. Webサムネイル

通常ノート上で、メイン窓の地球ボタンからURLを入力します。
選択URL・Markdownリンク、またはURLだけの行からコマンドで実行する方法もあります。
HTTP(S)のみを受け付け、ユーザー名・パスワードを含むURLは受け付けません。

1. URL、保存画像幅、タイトル枠の有無を入力する。
2. 一時的な非表示ブラウザでページ上部を撮影する。
3. プレビューで確認し、「保存して挿入」で確定する。
4. UUID名のPNGを保存し、本文へ引用形式の画像リンクを挿入する。

撮影画面は1280×900、保存幅は64〜1024px、既定256pxです。
タイトル枠は既定で有効。画像下部へ半透明の枠と最大2行のタイトルを描き込みます。
画像の寸法は枠を付けても変えません。

```md
> [![ページタイトル](<UUID.png>)](<https://example.com/>)
```

画像名はVault全体で重複を確認し、本文はパスを省いたファイル名で参照します。
`<>`はMarkdownのリンク先の範囲を明確にするために付けています。
有効なURL選択は置換し、未選択のボタン起動では開始時のカーソル位置へ挿入します。
その位置が先頭のYAMLプロパティ内なら、プロパティを壊さず閉じ区切りの後へ挿入します。
文章中の選択では引用が独立したブロックになるよう改行を補います。

独立した一時セッションを使い、普段のログイン状態は引き継ぎません。
ポップアップ・権限要求・ダウンロードは拒否します。
外部の撮影サービスや、ページへのNode APIの提供は行いません。
撮影全体の制限時間は既定25秒。白紙・単色・寸法不足の画像は最大3回の取得で再試行します。

画面の一定以上を覆う固定広告・ダイアログ等を、撮影用ページ内だけで隠します。
`visibility: hidden !important`を使い、閉じる・同意などのボタンは押しません。
これは属性・寸法による推定なので、必要な告知を隠したり、広告を除去できなかったりする場合があります。

キャンセル・失敗では元ノートへの挿入を行いません。
開始後にノートの本文・ファイルが変わった場合も挿入を中止します。
画像保存後に中止になった場合は、その画像の削除を試みます。削除できなければ保存場所を通知します。
挿入済み画像は本文リンクを消しても自動削除せず、孤立チェックから整理します。

## 8. タグ提案

管理フォルダ外のMarkdown文書を参照し、対象ノートへ付けるタグを提案します。
語彙の類似度、文書構成、近い文書のタグ、直接リンク先・リンク元のタグを材料にします。
学習例が十分なタグはSVMで再評価し、不足時は近傍文書等の投票を使います。
対象文書の語から新規タグ候補も作り、設定のストップワード等で除外します。

選択して確定したタグだけを対象ノートの`tags`へ追加し、重複を除きます。本文は変更しません。
表示スコアは候補の比較に用いる値であり、「正解の確率」ではありません。
LLMによる意味理解や、関連ノートへの内部リンクの自動提案・追加は実装対象に含まれていません。

## 9. 更新と再計算

| 契機 | 孤立判定 | エリア分析 |
| --- | --- | --- |
| 自動更新 | メイン窓または孤立窓の表示中に実行 | 距離エリアの結果があれば保持。結果がない場合は、手動で開くか更新した分析窓の表示中に従来の分析を実行 |
| 孤立窓の更新ボタン | 実行 | 実行しない。進行中の分析も中断しない |
| 分析窓の更新ボタン | 実行しない | 初回も含めて距離エリアを計算 |
| 全体再チェックのコマンド | 実行 | 強制的に再実行 |

メタデータの変更・解決、ファイルの作成・削除・改名等で自動更新を予約し、
既定1500msの待ち時間で連続イベントをまとめます。起動時に分析窓を復元しても、構造分析は更新操作まで待ちます。
分析窓を手動で開いたときは構造分析を実行し、接続が前回と同じ場合は完了結果を再利用します。
ノートを切り替えたときの関連ファイル表示更新は、分析とは別に扱います。

接続の比較はノード・隣接先の集合によって行い、列挙順の違いは変更とみなしません。
途中で中断・失敗した分析は完了結果のキャッシュにしません。
構造分析には10秒の時間制限と検出数の上限があり、失敗時は通知します。
表示中の分析が常に最新とは限らず、エラー表示と前回結果を区別して読む必要があります。

詳細窓は表示内容が変わらないときDOMを再生成しません。
選択グラフ・言語・色・グラフの後始末などによる再生成の必要性も確認します。
更新ボタンの回転は本文の描画省略と独立して更新し、窓ごとの処理に連動します。
メイン窓や孤立結果の更新だけでは、部分グラフを破棄しません。
プラグイン停止時には孤立・分析の表示待機を解除し、終了後の画面更新を抑止します。
窓の押下中に保留する再描画予約は一件にまとめ、閉じる・破棄する操作で解除します。
管理データ削除後の再チェックは孤立判定だけを更新します。

## 10. 設定と保存

設定はObsidianのプラグイン用`data.json`へ保存します。
保存要求時点のJSONの写しを作り、プラグイン内の呼び出し順で保存します。
保存失敗は通知し、保存を待っている操作には失敗を返します。後続の保存要求は継続します。
設定・管理記録・ノート・画像をまとめた原子的な保存ではなく、強制終了時に待機中の保存完了は保証しません。
Vault内のノート・画像と、プラグイン設定ファイルは別です。
実行中の管理フォルダも保存時も`state.folders`を正本とし、別の実行用設定との同期は行いません。
設定変更・リセット後は各機能が同じ参照を使い、既存のファイルを移動せずに新しい管理場所を参照します。

| 保存内容 | 主な項目 |
| --- | --- |
| 管理場所 | `folders` |
| 窓 | 表示状態、位置、部分グラフ窓サイズ、セクション開閉、`windowAppearance` |
| 分析表示 | 分類色、標準グラフへ追加した色グループの記録 |
| 孤立判定 | 対象外フォルダ |
| タグ提案 | ストップワード |
| 外部画像 | 埋め込み表示の有効・無効（既定は無効） |
| 取り込み復旧 | `pendingImport` |
| Web画像の管理 | `webThumbnailFiles`：生成パスと指定幅 |

Web画像の生成記録は、画像の表示幅と整理対象の識別に使います。
画像だけをコピーして記録を持ち込まない場合、元と同じ管理扱いになるとは限りません。
設定初期化でも、Web画像の所有記録は保持します。
ノートの分析結果や部分グラフのノード配置を、永続的な正本として保存する設計ではありません。

## 11. 制約と未確認事項

- FHD撮影は変更後にObsidianが落ちる報告があり、1280×900へ戻しています。
  FHD強制指定・描画エミュレーションの組み合わせが疑われますが、クラッシュログによる原因確定はしていません。
- Web撮影と部分グラフには利用者による実画面の確認があります。ただし全サイト・テーマ・倍率での網羅的検証ではありません。
- Web広告除去は汎用的な広告ブロッカーではありません。ログイン・Cookie画面の自動操作も行いません。
- 管理画像の改名・移動・削除後に、生成記録の不要項目を網羅的に清掃する専用機構はありません。
- 孤立削除は再確認しますが、同期や同時編集を含む全処理をトランザクションとして保証しません。
- `source`はローカル絶対パスです。Vault共有時にはパス情報も共有され、別PCで同じ場所が存在するとは限りません。
- 画像読み込みは1枚32MiB、元画像キャッシュは128MiB・64件を上限とします。
  デコード後の画像やGPUを含む、Obsidian全体のメモリ上限ではありません。
- 最小対応版・Windows以外・テーマ差・狭い画面での検証状況は公開前チェックで別管理します。
